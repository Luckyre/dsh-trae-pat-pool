# tool 轮次图片探测记录（2026-11-27）

## 结论与 v0.14.5 的范围

本次对指定 Trae 企业版路由的探测，没有获得模型使用 tool 轮次图片的正向证据。因此 v0.14.5 保留现有兼容策略：用户消息中的图片走 `image_url`；工具结果中的图片替换为 `[image omitted]`，保留文字及 `tool_call_id`。本版更新注释、文档和离线回归断言，不增加图片转发行为。

**HTTP 200 不等于模型看到了图片；一次未识别也不等于所有模型或所有请求格式均不支持。**

- 端点：Trae 企业版 `/api/ide/v2/llm_raw_chat`。
- 目录解析结果：`config_name=DeepSeek-V4.1-Flash-1017`，`model_name=DeepSeek-V4.1-Flash-1017__max`，实时目录声明 `multimodal=true`。
- 探测绕开插件号池的自动重试与换号，不修改席位冷却状态。本文不包含凭据或个人图片。
- A：用户文字 → assistant 工具调用 → tool 纯文本结果。
- B：同 A，在 tool 消息 `content` 末尾增加 `image_url`。

## 必须保留的证据边界

1. 上述观测仅覆盖该日期、企业端点、模型及手工追加 `image_url` 的消息形态；没有覆盖其他模型、API 或未来版本。
2. 红圆回读原型仍保留了“读取字母数字口令”的旧提示，任务与刺激不匹配。B 未描述目标图形是阴性结果，不足以证明图片一定在上游被静默丢弃。
3. C 的匹配主要来自 `reasoning_content`，最终可见 `response` 为空；不能把它写成成功的最终答案回读。
4. 更早的字符图试验存在手工复制图片数据及回答字段提取问题，不作为本次行为决策的可靠依据。原型曾把 HTTP 200 直接解释成可放开 tool 图，这个解释已撤回。
5. 没有请求编码缓存的新文件、没有找到持久化 warn 日志，都不能单独证明执行路径或多模态判定值。
6. 未见图片位置触发的 1210/假限流；本次不能把这类错误写成 tool 图片的已验证拒绝机制。

三份探索脚本存在上述判定问题，仅作为本地未提交原型保留，不随 v0.14.5 发布，也不作为可复现的正式验收工具。此版本没有再次发起真实上游探测。

## 后续若要重新验证

重新验证前应先整理一个默认离线、显式 `--send`、不接号池的探针：

- 使用匹配的中性任务与已解码验证的图片，避免刺激答案泄漏进文字。
- 断言 A/B 除一个图片部件之外消息完全一致，工具调用与结果保持配对；每条请求的 `session_id` 和 `conversation_id` 一致，并隔离不同试验。
- 检查完整 SSE：只从 `event=output` 分别汇总 `response` 与 `reasoning_content`；记录 HTTP、业务错误、结束帧、超时及截断状态。200 但响应不完整不能算通过。
- A 基线异常或猜中图形、C 未识别、任一请求出错/截断，均判为不确定；B 未命中只写“本次未识别”。
- 要声明正式支持，应有多个不泄漏答案的刺激与重复试验，并覆盖工具批次配对；不要把“未拒绝”自动转成生产开关。

## 离线回归能证明什么

现有消息翻译测试在映射中同时放入 user 和 tool 的已解析图片字节，验证：user 图片被序列化，tool 图片仍是占位文本、文字及 `tool_call_id` 保留。这仅证明插件当前策略没有改变，不验证远端模型能力。
