# PAT 号池方案 A：概览、账号卡片与会话账号标识

日期：2026-11-28

仓库：Luckyre/dsh-trae-pat-pool

设计基线：本地 main，HEAD 4fa66a9，包声明版本 0.14.5。工作区已有独立的图片探测修改；本设计不包含这些修改。

状态：用户已选择方案 A，并已审阅批准本文、要求按文档继续实现。开发位于隔离分支 feature/pat-pool-ui-a；安装、发布与远端推送另行授权。

## 1. 目标与范围

让用户在不展开凭据表单的情况下回答三个问题：号池里有几个账号、其中几个已验证可用；当前会话的请求实际使用哪个账号；填入 PAT 后是否已保存、验证是否通过。

采用方案 A：顶部号池概览、单列折叠账号卡片、对话输入栏账号标识。保留现有独立 Trae 设置页及模型设置页摘要入口。宽屏仍以单列卡片作为默认布局，窄屏自然换行。方案 B 双列卡片与方案 C 紧凑列表仅为已比较的备选，本期不提供布局切换设置。

本期包含逐账号验证、冷却原因与恢复时间展示、明确的凭据保存反馈、请求归属跟踪，以及实际使用账号对应的额度来源说明。本期不新增手动启停账号、锁定指定账号、模型白名单、历史用量分析、批量导入、自动发布或安装。

## 2. 已核实的现状

- 浏览器实现集中在 `client/client.js`。`SeatRow` 当前展开名称、PAT、控制台邮箱和密码的完整表单，缺少号池概览和健康状态。
- 多席位字段采用 600ms 停顿提交。`commit()` 在写入前移除草稿，失败时输入没有可靠的保留和重试流程。
- 凭据接口的 `describe()` 只暴露 configured/writable。configured 证明凭据存在，不证明上游接受它。
- `TraePatPool.status()` 已有逐账号冷却信息，但没有逐账号的已验证状态、凭据配置状态和页面完整投影。
- 全局 `lastMemberId` 由鉴权和选号共享。用它显示当前会话账号，会受到并发请求及后台操作影响。
- 现有 `SESSION_ROUTE` 返回每会话的模型、上游会话和时间，尚无实际账号和请求阶段。
- 输入栏 `QuotaChip` 请求 `scope=primary`，其额度不一定属于实际使用的账号。
- 现有调度先尝试没有排除记录的账号；全部账号被排除时还可能兜底尝试原账号。页面不能把“未检测”当作“已验证可用”，也不能宣称冷却绝对禁止调度。
- 直接填入 JWT 时，现有鉴权可只做本地解析；仅解析成功不足以宣称服务器验证成功。

以上为源码核对结果，不代表真实 Trae 账号、并发运行或页面视觉验收已通过。

## 3. 页面信息结构

### 3.1 页头与概览

标题“PAT 号池”，提供“刷新状态”和“添加账号”。“刷新状态”读取本地快照，不为每个账号兑换 PAT、不请求聊天接口。逐账号按钮“重新验证”才主动请求上游。

五个概览指标：

| 指标 | 精确定义 |
| --- | --- |
| 账号总数 | 有效、按 PAT 引用去重的账号集合大小；兼容旧配置的单 PAT 回退账号 |
| 已配置 PAT | 后端凭据解析确认存在非空 PAT 的账号数；不返回凭据值 |
| 已验证可用 | 当前凭据版本有服务器确认的鉴权证据，且当前未在冷却、未被拒绝、证据未过期的账号数 |
| 冷却 / 异常 | 有未到期冷却记录，或当前凭据被鉴权拒绝的账号数；卡片区分具体原因 |
| 待配置 / 待验证 | 缺少 PAT、从未验证、验证证据过期或检测因网络错误无法确认的账号数；卡片区分具体状态 |

这些指标是不同维度，不能相加作为总数。界面不使用含义不清的“激活”。“已验证可用”是状态证据，不承诺每个模型都可调用、额度充足或下次请求必定成功。

概览先加载占位，读取失败显示“状态暂不可用”和重试；不能把失败渲染成 0。

### 3.2 请求使用信息

设置页显示“最近模型请求使用”：明确标出所属会话、账号、模型、开始时间和运行/已结束/失败/已取消状态。只统计真实主对话请求；后台标题、压缩、目录读取、额度查询和令牌检测不覆盖它。设置页没有可确认的会话上下文时不显示“本会话”。

对话输入栏显示当前组件所绑定 sessionId 的请求账号：

- 未发过请求：“尚未使用账号”，不预言下次选号结果。
- 选号中：“正在选择账号”。
- 发出请求后：“账号名 · 使用中”。
- 请求结束：“上次使用：账号名”。失败和取消要显示对应状态，不能保留“使用中”。
- 发生换号：“主账号限流 → 已切换备用账号”；仅在新账号已实际选定后显示。不能把尝试换号当成换号成功。
- 轮转模式按每次实际请求更新，不把账号固定称作当前主号。
- 账号被移除后，最近请求仍保留当时的名称快照并显示“已移除”，不把它映射到同位置的新账号。

### 3.3 账号卡片

默认展示名称、优先级、验证状态、已保存状态、账号身份、额度摘要及其来源。需要关注的卡片提供原因和操作入口；筛选提供“全部”和“需关注”。默认顺序保持调度优先级，不因状态变化自动重排。

身份优先使用用户命名；其次使用已识别的 PAT 账号信息；最后显示“账号 N”。凭据引用键不能冒充邮箱或账号身份。

点击“管理账号”展开编辑区，保留改名、上下移和移除。初次添加账号及未配置账号默认展开 PAT 编辑。账号身份不在控制台配对不一致时被控制台邮箱覆盖。

卡片状态分别显示：待配置、待验证、验证中、已验证、验证暂不可用、冷却中、令牌失效。冷却显示限流/额度耗尽/上游不可用等标准化原因及预计恢复时间；没有精确恢复证据时注明“预计”。恢复时间到只代表重新成为候选，不能据此产生新的验证成功证据；只有此前验证证据仍有效，或后续验证/请求成功，才计入“已验证可用”。

“需关注”包含待配置、待验证、验证暂不可用、冷却和失效。验证中的账号显示进度，不显示成失败。

对于全部异常的现有兜底策略，状态区提供说明“当前没有已验证可用的账号；请求仍按现有重试策略尝试候选账号”。本次 UI 改造不悄然修改调度策略。

## 4. PAT 保存与验证交互

### 4.1 明确提交

PAT 改为显式“保存并验证”；取消 600ms 自动提交 PAT。控制台邮箱和密码也采用明确保存操作，避免用户输入到一半时写入凭据。普通账号名称可保留本地暂存与停顿提交，但必须有局部保存反馈和失败重试。

已保存 PAT 默认显示固定长度遮罩和“已保存”；遮罩不表示真实长度。通过“更换令牌”打开空编辑框。绝不读取、回显或复制凭据库里的已保存密钥；若允许显示输入，仅显示用户此次尚未提交的内容。

### 4.2 状态机与失败行为

`未填写 / 已保存` → `已修改·待保存` → `保存中` → `已保存·验证中` → `已保存·已验证 / 已保存·验证失败 / 已保存·暂时无法验证`。

- 写入收到明确成功响应后，重新读取 configured 元数据，再显示“已保存”；configured 元数据不能证明值相同或上游验证成功。
- 写入失败保留该账号的草稿，提供重试和取消，不显示“已保存”；其他账号仍可管理。
- 保存成功后清空已提交秘密的客户端草稿，再用主机端凭据进行验证。验证失败不撤销保存，不要求用户重复粘贴。
- 验证失败必须区分凭据拒绝、网络/服务异常和解析不兼容。网络错误不把 PAT 标成永久失效。
- 若写入成功但元数据读取失败，显示“写入已确认，状态确认失败”，允许重试状态读取；不自动重复写入秘密。
- 每个账号与字段有独立状态和操作序号。旧保存或验证响应不能清除新草稿、覆盖新凭据状态或污染被移除的账号。
- 编辑时关闭页面或切换账号不会自动提交未保存 PAT；只在组件生命周期内保存草稿，离开编辑时提示未保存更改。草稿不写 localStorage、日志或配置文件。
- 环境变量等只读凭据显示来源及“只读”，禁用写入入口，仍可读取状态和主动验证。

### 4.3 验证的证据边界

逐账号验证从主机端解析凭据，使用独立账号鉴权对象，不调用会推进轮转游标的 `pool.get()` 或 `prepare()`。PAT 兑换成功可作为服务器鉴权证据；直接 JWT 必须经过既有 `GetUserInfo` 鉴权接口并成功解析身份，才能称为服务器验证通过。需要时可对 PAT 同样读取身份。

验证不发聊天、不消耗生成额度、不修改会话归属。验证只证明该账号鉴权通过，不证明所有模型权限或企业控制台额度接口可用。

证据绑定凭据版本、检测时间和有效 JWT 的到期时间；过期后转为待验证。服务器重启可恢复已有冷却事实，但不恢复没有有效证据的“已验证”状态。更换 PAT 后清除旧验证结果，旧异步结果必须按凭据版本丢弃。

新验证通过不清除额度/限流冷却。凭据明确被拒绝必须针对本次实际账号记录，不能把并发中的另一个账号标坏。

## 5. 状态与接口设计

### 5.1 账号状态投影

新增只读 `GET /api/dsh-trae-pat-pool/pool`，由同一连接注册机制提供 Host/Origin 与登录保护。返回统一投影：mode、attempts、updatedAt、summary 和 seats。

每个账号投影包括 seatId、name、priority、configured、writable、validation、checkedAt、validatedUntil、reasonCode、retryAt 和最小身份信息。configured 读取失败用 unknown，不当作 false。响应不携带 PAT、JWT、密码、请求头或上游原始错误正文。

状态读取不得触发 PAT 兑换、选号、轮转、聊天或全部席位额度刷新。首次读取可解析凭据是否存在，但只返回布尔状态；凭据事件、配置变化及实际请求结果更新缓存。

### 5.2 主动验证

新增 `POST /api/dsh-trae-pat-pool/pool/validate`，JSON 请求体仅包含 `seatId`，不接收令牌内容。必须验证 seatId 仍属于当前有效账号集合；未知或已移除账号返回 404。错误 JSON/无效类型返回 400。

逐账号并发验证去重，接口绑定当前凭据版本；取消或凭据更换后旧结果不发布。返回结构化验证结果及新的账号投影。上游错误只投影标准化原因和安全提示。

全局“刷新状态”不调用此接口。本期不做全账号自动验证按钮，也不在浏览器轮询中重复验证。

### 5.3 请求归属与并发正确性

扩展 `SESSION_ROUTE` 的现有返回，增加可空的 request 对象：requestId、phase、seatId、seatName、startedAt、finishedAt、switches 与安全原因码。保留原有字段契约。

请求归属在 adapter 的实际选号/发出请求位置捕获，沿重试和流式处理链显式传递 memberId。单 PAT 模式也规范化为真实 PAT 引用，不能用空字符串导致无法匹配账号。

归属由 `(sessionId, requestId)` 隔离。重叠请求不能被一个全局 lastMemberId 代表；同一会话显示最新开始请求，旧请求结束不能清除新请求的运行状态。跨会话请求始终独立。流内错误也用该请求的 memberId 记录失败，避免改造后的页面展示了串号的冷却事实。

仅保存有限数量的最近主会话快照，沿用现有跟踪容量；每次请求的换号列表限制为最多 10 条最新记录。不保存聊天正文或永久账号使用历史。

设置页的最近请求使用上述主请求快照，随 pool 响应的 latestRequest 字段返回。对话徽标使用 `GET /api/dsh-trae-pat-pool/session?session=<id>&view=usage`：这个新模式只返回已记录的 request 投影，request.phase 固定为 selecting / running / completed / failed / cancelled；没有记录时为 null。该模式必须在原有诊断查询之前分流，不重新鉴权或触发 userInfo。未提供 view=usage 时沿用现有会话与诊断响应，保持旧客户端兼容。

### 5.4 输入栏额度

新增 `GET /api/dsh-trae-pat-pool/quota?seat=<seatId>` 的定向读取；seat 必须属于当前集合。保留原有 scope=primary 和全部账号接口以兼容旧客户端。

输入栏账号徽标独立于额度显示。额度读取失败、没有控制台或没有有限百分比时，账号标识仍显示，额度显示“未知”或省略数字。请求账号变化立即丢弃旧账号额度展示，再读取新账号缓存；迟到响应必须验证 sessionId 和 seatId 后才应用。

账号行、实际请求快照和定向额度增加 `credentialVersion`：它是主机内生成的不透明随机版本标识，不是令牌、令牌片段或秘密哈希。请求保存选号时的版本，额度附带所查询凭据的版本。即使 seatId 相同，版本不一致也不能把新凭据的额度附到旧请求；此时保留旧请求的名称/身份快照并显示凭据已变更、额度未知。页面重载后仍按服务器版本判断，不能只靠浏览器内存缓存隔离。

尚未实际选号时，不把主席位额度和“当前账号”合并；需要展示历史时明确写“上次使用”。不为徽标查询整个号池，也不把共用控制台的数字相加成号池总额度。

### 5.5 刷新与资源回收

Trae 设置页可见时每 15 秒读取轻量号池快照；对话区有运行中 Trae 请求时每 2 秒读取会话账号状态，空闲时每 30 秒读取，结束后主动补读一次。后台标签页暂停轮询，重新可见时立即补读。接口故障采用 5、15、30 秒退避，不重复弹出错误。

凭据保存与验证完成、账号增删排序后主动刷新相关状态。使用同一页面共享 store，避免多个徽标各自重复请求。组件卸载、插件 dispose、会话切换时清理定时器并取消可取消请求，丢弃旧响应。

额度沿用缓存与低频刷新，不能跟随 2 秒状态轮询强制请求控制台。客户端语言走现有 zh/en locale，容器、色彩和控件沿用 DSH 主题 token；成功/失败同时给文字，不只靠颜色。

## 6. 实现边界

建议在现有入口旁增加聚焦的小模块，分别负责账号验证投影、请求归属跟踪、客户端账号卡片与局部编辑状态。避免继续把全部状态机堆进现有大函数。

主要接入点：`src/trae/pool.ts` 的账号和失败接口、`src/adapter.ts` 的实际选号与流生命周期、`src/index.ts` 的连接路由与凭据事件、`client/client.js` 的设置页/输入栏/store。涉及测试时增加对应入口导出，不为测试复制业务谓词。

配置仍通过 DSH settings/configEditor 保存；秘密仍通过 credentials 写入，只保存引用名。旧 seats=[] 的单 PAT 配置、账号顺序、故障转移和轮转模式继续兼容。新状态接口是增量，旧客户端不会因新增字段失效。

本期不改 conversation_id 的生成规则、不改变图像转发、不混入工作区现存图片探测修改。发布安装和 GitHub push 不在本次设计确认的授权范围内。

## 7. 验收与验证

### 7.1 业务验收

1. 5 个账号包含缺 PAT、有效 PAT、失效 PAT、冷却和未验证组合时，概览符合定义；重读失败不渲染成零；单 PAT 回退账号同样准确。
2. 新 PAT 输入后立即显示“待保存”；保存前凭据库不变化；成功、写入失败、验证失败、元数据失败四条路径文案与实际结果一致。
3. 写入失败可原地重试，草稿不丢失；成功后草稿不残留；新编辑不被旧响应清除。
4. 无额度账号可显示鉴权通过；额度接口失败不抹掉当前账号；共享控制台不累加成总额度。
5. 两个会话同时使用不同账号时，徽标及冷却归属互不污染；同会话重叠请求的晚到完成不覆盖新请求。
6. A 拒绝后改用 B，运行账号和换号提示匹配实际请求；无备用可用、请求取消、流中报错均能退出“使用中”。
7. 模型目录读取、额度查询、检测 PAT、标题和压缩请求均不能覆盖主会话账号。
8. 轮转状态读取不推进游标；逐账号验证不触发聊天；后台页面不持续高频读上游额度。
9. 删除或重排账号、切换会话、更换 PAT、插件卸载等情况下没有错配标签、旧结果闪回和遗留定时器。
10. 深色/浅色、窄屏、长账号名、未知身份和键盘操作可用；英文文案不出现原始 locale key。

### 7.2 代码验证
